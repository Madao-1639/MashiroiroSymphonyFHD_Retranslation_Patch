# `.scn` 文本模型

剧情不是 KAG 的 `.ks`，而是编译进 **PSB** 的结构化对象（外壳见 [file-formats.md](file-formats.md) §2）。
本文说明：哪些字段是要翻译的文本、哪些是内部键、替换文本时必须同步维护什么。

数据规模（本作实测，用于判断口径是否成立）：

| 项 | 民汉补丁（日文原版 FHD） | Steam 版（简中域） |
|---|---|---|
| 脚本 | 277 | 202 |
| 场景（`label`） | 377 | — |
| 对白行 | 69,544 | 53,218 |
| 选项 | 11 | 11 |
| 对白总字数 | 1,219,457 | 799,744 |

## 1. 场景（`root["scenes"][i]`）

| 键 | 含义 | 可翻译 |
|---|---|---|
| `label` | 场景标签（`*start`、`*normal`、`*replay_xx`、`*dummy1`…） | ❌ 跳转目标 |
| `firstLine` | 该场景第一行的全局行号 | ❌ |
| `lines` | 命令流（`envupdate`/`update`/`wait`/`bg`/`anm_*`…），含资源名与内部键 | ❌ |
| `texts` | 对白行数组 | ✅ 见 §2 |
| `selects` | 选项数组（有分支的场景） | ✅ 见 §4 |
| `nexts` / `preevals` / `postevals` | 跳转与标志位（`f.ag_route_1 = 0`、`sf.clear_sn = 1` 之类的 TJS 片段） | ❌ |
| `title` / `spCount` / `version` / `selectInfo` | 元数据（本作 `title` 全为空串） | ❌ |

## 2. 对白行（`scene["texts"][i]`，固定 5 元）

```
[0] speaker     说话人显示名（string|null）                    ✅ 可翻译
[1] pages[]     分页数组                                       见下
[2] attrs[]     每页属性 dict：name=语音角色键, pan, type, voice=语音文件名   ❌
[3] flag        本作恒为 64（不动）
[4] {data, env, …}  命令容器（转场 / 立绘 / BGM 等）              ❌
```

分页两种形态：

```
3 元：[voice_gate|null, text, length]
5 元：[voice_gate|null, text, length, text_plain, text_plain]
```

| 字段 | 含义 | 处理 |
|---|---|---|
| `[0]` | **逐页**说话人覆盖（`？？？`、`全体女生`…），非空时覆盖行首 speaker | ✅ 可翻译 |
| `[1]` | 正文；换行是字面两个字符 `\` `n`；行内标记见 §5 | ✅ 翻译目标 |
| `[2]` | `length`，口径见 §3 | ⚠️ 替换后必须重算 |
| `[3]` | `text_plain`：去掉 `\n` 的同一段（`[3]`/`[4]` 正常共用一个字符串槽） | 见 §6 |

实测分布：3 元分页 48,823 页 / 5 元分页 20,721 页（同一份数据里两种并存，**没有 `text_plain` 不代表缺失**）。

## 3. `length` 字段的三种口径

| 数据来源 | 口径 | 判据 |
|---|---|---|
| 某民间汉化（基于日文原版） | **原始长度**：行内标记与 `\n` 全算 | 69,539/69,544 页满足 `length == UTF-16 码元数` |
| Steam 官方（简中 / 繁中域） | **显示长度**：删掉 `%NNN;`、`#RRGGBBAA;`、`#;`、`\k`、`\p` 后再算，`\n` 仍算 2 | 含标记的 84（简中）/ 85（繁中）页全部符合；其余两派等价 |
| Steam 官方（英文域） | **显示长度且字面 `\n` 计 0**：`%NNN;`、`#RRGGBBAA;`、`#;`、`\k` 全部不算，`\n` 也不算 | 138 页不符合「UTF-16 码元数」，差值逐条等于被删标记的字符数（含 `\n` 的 2） |

例：`%205;磅──！！！` → 官方记 `6`，同一句在汉化侧会记 `11`；英文域 `“Hmmm, okay.”\n“Okay, then...”`（30 码元）→ 记 `28`。

规则：**回写哪一版就按哪一版的口径算，同一批产物不得混用**。本仓库统一封装为`tool/scn.py::page_length()`（显示长度；`\n` 仍按两字符计 —— 对简中 / 繁中域正确，**英文域会多算 `\n` 的 2**，但本项目的回写目标只有中文域，不影响）。字段只影响自动/快进节奏，写错不崩。

## 4. 选项（`scene["selects"][i]`）

```
{ render:1, selidx:0, storage:"…", target:"*start", text:"是" }
```

- `text` 是选项文本 → ✅ 可翻译。
- `button: "yes"|"no"` 形态没有 `text`，按钮文字来自 UI 层（`.tjs`），不在脚本里。

## 5. 行内标记（必须原样保留）

| 形式 | 例子 | 作用 |
|---|---|---|
| `%NNN;` | `%205;嘭！！！`、`%164;“出去──！”` | 字符/语音标记（角色或特效索引） |
| `#RRGGBBAA;` | `#000033ff;` | 文字着色 |
| `#;` | `……#;也要` | 颜色复位 |
| `\n`（字面反斜杠+n） | `——是啊。\n嘴唇…` | 强制换行 |
| `\k` / `\p` | `…\k%123;不是…` | 点击等待类标记 |
| `\\` | `anim\\bg\\img_october` | 转义反斜杠（仅开发备注脚本里出现） |

匹配/翻译时把它们当**不参与翻译的记号**：数量与位置必须守恒。

## 6. 回写不变量与实现（阶段 4 已验证）

1. `length` = 目标版口径（§3），每条重算
2. 行内标记数量与相对顺序不变（§5）
3. 目标版是 3 元分页时只写 `text`；沿用 5 元分页才需要自己补 `text_plain`（本作 Steam 侧全部是 3 元，民汉侧两者都有）
4. **不需要完整对象图序列化器**：文本是字符串池里的槽，`length` 与文本引用都是页面数组里的**定宽内联字段**，两者都能**原位改字节**（同字节宽度 ⇒ 后续偏移不动）。只有「一个字符串槽被多个页面共用、且这些页面要写不同译文」时才需要**追加**新槽（`rebuild(extra_strings=...)`，新槽号 = 池尾），并把该页的引用原位改指向新槽（新槽号必须仍落在旧引用的字节宽度内，否则只能保留多数票文本）
5. 同理，**内联整数的类型字节必须按族写回**：整数 `0x04+width`、字符串引用 `0x14+width`（写成整数类型会让解析器把文本当数字，页文本变成空串——实测踩过）
6. 改写后回读校验：`length == page_length(text)`、正文与预期一致、标记数一致、`voice` 未变、行数/页数未变（`script/writeback.py verify`，本作 199/199 脚本、52,117 页通过）

### 6.1 已知的不可分离结构：共享页列表对象

官方脚本会把**完全相同的页列表去重成同一个对象**（PSB 图是 DAG，不是树），于是两个不同 `row`可能共用同一个页数组——连 `length` 槽都共用。这类行**只能写同一段文本**，除非做对象图手术（新增页列表 + 改父数组计数 ⇒ 需要完整序列化器）。

本作实测：52,133 页里 **13 页**受此限制（另有 3 页受「引用只有 1 字节、而新槽号 ≥ 256」限制），按多数票写入；逐条清单由 `script/writeback.py apply` 写入 `tmp/_report_apply.json`。差异都是近义短句，可接受。

### 6.2.1 耗时构成（为什么这一步慢）

单个 3 MB 的脚本实测：解析 PSB 图 2.2 s、按路径记录槽位 2.4 s、重建字符串池 0.05 s、mdf 外壳 zlib(9) 2.3 s。即**纯 Python 的对象图遍历**与**压缩**是两头开销；`fetch` 另需把 1.7–1.9 GB 的加密归档整包读进内存再解密（`Hxv4Archive` 目前是 `fp.read()`）。
因此 `apply` 默认按脚本并行（199 个脚本从 6.5 分钟降到 1.7 分钟），`verify` 未并行（约 3 分钟）。

### 6.3 匹配/回写口径：位置映射 + 采纳民汉顺序

- **一律按位置映射**（`chs (script, scene, row, page) → steam 同键`），不做交叉映射。
- 全量复核（201 脚本 / 29,745 条无语音行）记录到 **10 个脚本共 14 处偏移段**（`resource/match/offsets.jsonl`）：`reorder` 11 处、`split` 1 处、`extra` 2 处（其中 `seアフター_01` 为 `rewrite+extra`）。它们只作为**事实记录**，全部裁定为 `action = "no_action"`——回写仍按位置写，最终呈现的是民汉语序（见 `doc/version-diff.md` §7.3）。
- 依据：民汉补丁是对日文原版 PSB 的**原位字符串替换**（结构、行数、voice 槽全部继承原版），其语序即原版语序，且译文质量高于官中。
- 残余不确定性：日文原版无法做终审——原版 `mashiro_fhd.exe` 的 Hxv4 参数与 Steam 版不同，`resource/hxv4/profile_live.json` 打不开 `MashiroiroSymphonyFHD_original/*.xp3`（`Hxv4 mapping table tag mismatch`）。官方三语逐行同序只能证明官方内部一致（三语同源）。
- 影响面：偏移段涉及的行**全部无语音**（`needs_review` 行 100% 无语音，见 §7），位置写入不会造成语音不同步。
- **反例（官方后遗症，不是我们的风险）**：`seアフター_01.txt` `*start` row 30–37，官方的文本比自身语音慢一格（同一行两侧 `voice` id 相同、文本却是相邻句）。采纳民汉后这些行反而重新对上语音，因此该段属于「采纳民汉更正确」。

### 6.2 回写流水线（`script/writeback.py`）

| 子命令 | 作用 |
|---|---|
| `fetch` | 从 3 个加密归档解出**简中域**脚本到 `tmp/zhcn_psb/`（带 `file_hash` 清单） |
| `roundtrip` | 闸 1：零改动重建 body 逐字节相同；闸 2：单条字符串变长/变短后仍能解析且池内容一致；闸 3：每页 `length` 内联槽位置与提取结果逐页一致 |
| `apply` | 位置映射写入文本 + 选项文本 + 重算 `length` + 共享槽分流，产出 `tmp/out_zhcn/` 与 `tmp/_report_apply.json`；`--jobs`（默认 8）按脚本并行 |
| `pack` | 打成明文 xp3（条目名 `<script>.scn`，索引 zlib） |
| `verify` | 读回包：条目名哈希、文本、标记、`length`、`voice`、结构逐页校验 |

## 7. 场景结构与版本的对应关系（本作实测）

两版共有 201 个脚本、243 段场景，**对白条数零差异**，Steam 的 53,218 条对白可按`(脚本, 场景 label, 行号, 页号)` **100% 一一对应**；同一位置的两条文本是同一句原文的不同译本。

Steam 版缺失的 76 个脚本（SANA EDITION 60 / PSP 追加路线 15 / 开发备注 1）在移植时直接跳过。

逐条核对过的对齐统计：

| 项 | 结果 |
|---|---|
| 场景数 | 243，**条数差异 0** |
| 对白行 | 53,218，**每行页数差异 0** |
| 旁白 / 对白性质（`speaker` 是否为空） | 53,218 / 53,218 一致 |
| 语音 id（`pages[].voice`） | 两侧都有语音的行 **23,470**，**id 100% 相同**；两侧都无语音 29,748 行 = 旁白 18,997 + 主人公（新吾）10,750 + 「？？？」1 |
| 逐页说话人（`pages[0][0]`） | 民汉 212 行有值；Steam 34,221 行有值，其中 21,825 与行首 `speaker` 相同、12,396 不同（例：`桜乃` / `櫻乃`） |
| 民汉日文残留 | 共同脚本内仅 14 行 |

⇒ 匹配与回写都以 `(脚本, 场景, 行号, 页号)` 为对齐键；**语音 id 相同的 23,470 行可直接判定为同一句**；其余（无语音的 29,748 行）才需要语义判断。**回写时行首 `speaker` 与逐页 `pages[0][0]` 两处都要处理。**

> **语音锚点的覆盖边界（实测）**：语音 `id` 只挂在**配角台词**上——爱理/樱乃/安洁/纱凪/美羽/隼太等 100% 有语音；**主人公（新吾）10,750 页全部无语音**（这是设计如此，不是漏失），旁白 18,997 页同样无语音。所以 `pairs/` 的 `needs_review` 恰好等于「旁白 + 主人公台词」，靠语音锚点无法覆盖，只能做语义判断（阶段 3 已全量完成，见 `doc/version-diff.md` §7）。

阶段 3 **全量复核**（201 脚本 / 29,745 行，逐条读两侧原文）给出**结构异常的完整清单：10 个脚本共 14 处偏移段**（11 处 `reorder`、1 处 `split`、1 处 `extra`、1 处 `rewrite+extra`；均在无语音区内部、不传播、**场景行数守恒**），机器可读版见 `resource/match/offsets.jsonl`（每条带 `action = "no_action"`）。
**回写仍按位置映射（`chs row N → steam row N`），采用民汉语序，不做交叉映射**（民汉侧是原版 PSB 的原位字符串替换，语序即原版语序；哪侧相对日文原版换序无法定案，勿猜测）。
带语音行不可能错位：全量 23,470 行 voice id 零不一致，且没有「只有一侧有语音」的行；唯一反例是 `seアフター_01.txt` row 30–37 官方自身文本与语音错开一格（详见 §6.3）。

### 7.1 语言域之间的结构一致性（匹配结果可复用）

`resource/steam_text_zhcn`（简中）与 `resource/steam_text_zhtw`（繁中）逐脚本逐页对比结果：

| 项 | 结果 |
|---|---|
| 共有脚本 | 198（简中域 199 里 `scenemode.ks` 无对白；繁中域 202，多出 3 个 `seアフター_*`） |
| 对白行 / 页 | 52,133 / 52,133，一个不差 |
| 场景 label、`row`、`flag`、页数、`char_id`、`alt_speaker`/`plain` 有无、选项 `index` | **全部相同** |
| `voice` id | 23,019 条带语音页全部相同，零不一致 |
| 译文字符串 | 51,325 / 52,133 页不同（繁简 + 措辞） |
| `length` | 78 页不同 |
| 文本字符串槽下标 `text_idx` | 47,763 / 52,133 页不同（**两域字符串池排序不同**） |
