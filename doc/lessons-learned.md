# 判据与守则

跨主题的工程规则。格式与算法本身的不变量分别写在 [file-formats.md](file-formats.md)（容器/序列化）、
[text-model.md](text-model.md) §6（文本回写）、[hxv4.md](hxv4.md) §6（加密层）里；本文只收
**做任何一步都要先满足的判据**。

## 1. 改写工具的验收闸：零改动往返必须逐字节一致

- **判据**：不做任何修改地重建，PSB body 与原始**逐字节相同**
- **原因**：这条一旦成立，后续所有改写差异都只可能来自"你改的那部分"，排错范围立刻收敛
- **做法**：`tool/psb.py::rebuild({})`；`.scn` 层允许 zlib 压缩流不同（解压后比对 body）

## 2. 脚本的身份来自内容，不来自文件名

- **判据**：加密归档解出来的文件没有真名（伪名/哈希名），身份只能取 PSB 的 `root["name"]`
- **做法**：解析入口按**魔术字节**分类（`mdf\0` / `PSB\0`），并跳过没有 `scenes` 的 PSB
  （`.pimg` 之类也以 `PSB\0` 开头）

## 3. 同名副本按归档优先级取舍，且必须比对内容

- **判据**：krkrz 后注册者优先（`patch > data_fhd > data`）
- **做法**：按容器排序取最后一份；同内容视为重复副本，**不同内容视为覆盖** ——
  两者都要在索引里留痕（`_index.json` 的 `duplicate_copies`），不能静默丢

## 4. 长度字段按目标版口径重算，同一批产物不混用

- **判据**：同一批文件里出现两种口径 ⇒ 一定有一半是错的（详见 [text-model.md](text-model.md) §3）
- **做法**：单一函数 `tool/scn.py::page_length()`，校验脚本对两种口径分别计数

## 5. 参数类数据以运行态为准，静态派生值不作为判据

- **判据**：加密层参数（key / nonce / holder / context / lanes）由运行时算出；
  静态派生可能给出"能骗过部分校验"的错误值（[hxv4.md](hxv4.md) §5）
- **做法**：从运行中的进程读一次 → 落成 profile → 用**独立路径**（游戏内解包）比对产物

## 6. 验证判据要独立于被测实现

- **判据**：自写实现与"工具自产自销"的一致性证明不了正确性
- **做法**：① 密码学原语用公开测试向量；② 离线解包结果与另一条独立路径（游戏内注入式解包）
  逐字节比对；③ 取样覆盖：小文件全部、大文件抽查

## 7. 解析器遇到不认识的东西要报错，不要静默跳过

- **判据**：静默跳过会把"格式假设错了"伪装成"这类文件不存在"
- **做法**：未知类型/长度不符/校验失败 → 抛异常并带文件名与偏移；确需跳过时（如 `.pimg`）
  要显式记录原因并计数

## 8. 代码级：哨兵不要用 `None`，遍历不要靠递归

- **判据**：对象图里本来就有大量真 `None`（PSB 的 `null`），把 `None` 当"从根开始"的哨兵
  会让遍历从根重启、无限递归
- **做法**：独立哨兵对象 + 显式栈；实测这类数据嵌套深度只有十几层，"递归太深"通常不是真因

## 9. 中间产物与临时文件的去向

- **判据**：解包/提取的中间结果体积大且可由脚本重建
- **做法**：只把**文本与参数**这类小而不可再生的结果放进 `resource/`；
  解包产物、调试脚本、日志一律放 `tmp/`（`tmp/` 不入库），任务结束清空

## 10. 文档纪律

- 结论写进**对应主题的文档**，不另建"总结/汇总"文档（同一结论只允许存在一处）
- 只写当前成立的结论，不写探索过程与试错史；跨作不确定的结论标注 **【跨作需重验】**
- 每条结论都要能追到一个判据（可复跑的命令、可对照的文件指针、或另一条独立路径的验证）
